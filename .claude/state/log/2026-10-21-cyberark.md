# 2026-10-21 — CyberArk 整合設計

客戶提到兩個功能：代登（PSMP）、用 SSH 定期換密碼（CPM）。

## 定案
- 人進主機：AD 帳號登入 CyberArk → PSMP 代登操作機（cpadmin），錄影。
- 操作機 → 各主機：cpadmin 的 SSH 金鑰由 CyberArk SSH Key Manager 產生與輪替；公鑰由 CPM 推到各主機
  `authorized_keys`（含操作機自己）；私鑰作業當天從 PVWA 取出（填變更單），放 `~/.ssh`，用完刪。不走 PSMP。
- sudo：OS 團隊依變更單開放、做完收回（不假設有 OPM）。
- svc-mds-bind：建議只保管不輪替（唯讀帳號）；要輪替就配合 broker 滾動重啟。
- Secret Protection vs 純 CyberArk provider：選 Secret Protection，master key 由 CyberArk 保管、開機時注入；
  master key「CyberArk 保管、我們輪替」，CyberArk 端設為不自動輪替。
- SCRAM 自動輪替：CyberArk 無內建 plugin；第一階段只保管、人工輪替。
- 整體分三級：順的（PSMP、SSH key、root 輪替）做；只保管做；應用層自動輪替不做。

## 給客戶／原廠的問題
- 客戶：操作機可否持有受管金鑰（或每條連線都走 PSMP）；sudo 開放流程；是否啟用 SSH Key Manager；svc-mds-bind 是否納入輪替。
- Confluent 原廠：SCRAM 輪替建議做法；零中斷（dual account）；csid-secrets-providers 的 client 是否自動重取；CPM 自訂 plugin 案例。
  （原廠已回 csid-secrets-providers：解「取密碼」，不解「輪替」。）

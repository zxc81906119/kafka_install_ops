## 教訓
- lab 的「現行 CA」不能用目錄存不存在判斷（21.3 跑過會留下 `ca/g2`，但腳本版從零裝的平台信任 g1）：
  要看哪個目錄的 `issuing.crt` 能被操作機的 `bank-root.pem` 驗證通過。選錯 → 9.3 的 `chain=FAIL`、REST 回 000。
- MDS 把寫入轉給 master writer，broker 重啟後 writer 剛換會短暫回 `50003 not the current leader`：刪 binding 要重試（手冊三次、腳本 `retry 3 5`）。
- `kafka-topics --describe` 的 `PartitionCount … ReplicationFactor` 之間是 tab，`grep -oE` 後要 `tr -s '\t' ' '`。
- **REST Proxy 只放行白名單 CN**（第 12 章 `auth.ssl.principal.mapping.rules`，來源 `apps.txt`）：新 REST 應用程式光有憑證與 binding 還是 401（`CertificateLoginService: Failed generating principal`）。
  手冊 27.3 補上：兩台 REST 的規則加 CN（deployed 檔與 ops02 副本都改）＋ 12.1 的 LB 停用→重啟→恢復六塊；腳本 `rest_allowlist`：加進 `conf/apps.txt`、重跑第 12 站。下線時反向。
- REST v3 produce **一律 HTTP 200**，成敗看回應 JSON 的 `error_code`（200／40301）：用 `-w %{http_code}` 判斷會把被拒當成功。

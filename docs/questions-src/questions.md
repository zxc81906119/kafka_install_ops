# 1. 怎麼看這份文件

每一題列出三件事：要問什麼、為什麼要知道、銀行還沒有答案時我們先怎麼做。「我們的預設」是在模擬環境驗證過的做法；銀行的答案不同時，我們依答案調整安裝步驟。

請各負責團隊填寫答案後回覆；同一題有多個團隊相關的，請由第一個列出的團隊彙整。

# 8. CyberArk（Secrets 團隊）

已知：只有 PAM（PSM／PSMP 代登、SSH 金鑰輪替），沒有 CCP、Conjur，程式不能直接向 CyberArk 取值。平台的密碼加密後留在主機上（Confluent Secret Protection），解密用的 master key 由 CyberArk 保管。

| # | 問題 | 為什麼要知道 | 我們的預設 |
|---|---|---|---|
| 8.1 | 平台加密用的兩個值（passphrase、master key）放哪個 safe？誰可以取用？ | 兩個都要存：master key 用於重建主機與復原，passphrase 用於輪替 master key | 同一個 safe、兩個 object 分開授權：passphrase 只給平台工程師 |
| 8.2 | master key 產生後由誰存進 PVWA：Secrets 團隊代存，還是平台工程師有權限自己存？ | 確認存好之前不會上線 | Secrets 團隊代存，存好後回覆單號 |
| 8.3 | 從 PVWA 取用（cpadmin 私鑰、passphrase、master key）是否要雙人覆核？要填什麼單號？ | 安裝與輪替都會用到 | 依變更單號取用 |
| 8.4 | cpadmin 的 SSH 金鑰：是否由 CyberArk 產生、定期輪替、推送公鑰到各主機？輪替排程多久一次、變更時段內能否暫停？公鑰可否加 `from="操作機 IP"`、`restrict` 限制？ | 操作機要用它連到每台主機；做到一半金鑰被換，之後的 ssh 全部失敗 | CyberArk 管理；變更時段內暫停輪替；輪替後平台工程師重貼 agent（手把手 20.6）；公鑰限定只能從操作機登入 |
| 8.5 | 應用程式現在怎麼拿資料庫密碼？Kafka 的應用程式密碼是否照同一套方式交付？ | 決定應用程式密碼的交付流程 | 照現行方式；新密碼由維運選單產生後交 Secrets 團隊登錄 |
| 8.6 | AD 查詢帳號 `svc-mds-bind` 的密碼若由 CPM 管：可否關掉自動排程、改成依變更單觸發並通知平台？或開 A／B 兩組帳號交替？ | 這個密碼加密後固定在主機上，CPM 悄悄換掉的話，broker 下次重啟時權限服務起不來 | 依變更單觸發、單一帳號；CPM 換完由平台工程師從 PVWA 取新值、更新密文、滾動重啟（約 10 分鐘，不中斷應用程式） |
| 8.7 | 平台加密用的 master key 多久輪替一次？依哪一條規範？規範是否要求「加密金鑰本身」（data key）也定期更換？ | 決定 16.6 的輪替週期；data key 定期更換要另外排程 | master key 每年輪替一次，保管人異動時也換；data key 不例行更換，懷疑外洩時改換密碼本身並重新加密 |
| 8.8 | 經 PSMP 登入操作機後：是否有指令白名單（要能執行 `ssh-agent`、`ssh-add`、`ssh`、`scp`、`sudo`）？錄影或指令紀錄是否會記下鍵盤輸入的內容？ | 平台工程師要在操作機開 ssh-agent、從 PVWA 貼私鑰與密碼 | 允許上述指令；貼上機密時一律關閉回顯（`stty -echo`／`read -s`），畫面與錄影不會出現值 |

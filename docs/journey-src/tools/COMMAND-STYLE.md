# 指令寫法規則（手冊、install、opmenu）

讀者是不熟 shell 的安裝與維運人員。最優先是**看得懂、改得動**，寧可多幾行、有重複，不為簡短而壓縮（使用者 2026-11-05 定案）。
新增或修改指令後跑 `node docs/journey-src/tools/lint-commands.js`。

## 共通規則

1. 一行一個指令；步驟用註解編號；不相關的幾行之間空一行。
2. 判斷寫完整的 `if … then … fi`，迴圈寫完整的多行 `for … do … done`；不用 `a && b`、`a || b` 串接指令。
   `if` 條件內的 `[ … ] && [ … ]`、`awk` 語法裡的 `&&`、`||` 不算。
3. 不巢狀 `$( $(…) )`：先把內層放進有名字的變數。算術裡的 `$(date +%s)` 可以。
4. 一行不超過 120 字（不含設定檔內容與套件清單）：把憑證參數、URL 放進變數，或用 `\` 分行，一行一個參數。
5. 文字處理：一條管線最多 3 段，再長就分步存進變數並加註解。`awk '{print $2}'` 這種取欄位可以；複雜的 `awk` 程式與帶群組的 `sed` 要改成 `grep -o`＋`cut`，改不了就在上面寫一行輸入與輸出的例子。
6. 只用 bash 與 RHEL 標準指令（ssh、curl、openssl、sed、awk、grep、tar、dnf、systemctl）和 Confluent CLI。**不要用 `jq`**：主機沒有安裝，也不在銀行的需求清單。
7. 密碼不寫進指令也不印出來，執行時從 0600 檔讀進變數。

## 手冊（journey.md）

8. **人照打的指令不定義函式，直接寫指令**；同樣的指令重複出現沒關係，每一塊都看得出在做什麼。
   例外：手冊用 `cat > 檔案 <<'EOF'` 寫到磁碟的腳本（例如 `metadata-backup.sh`）是交付的程式，可以有函式。
9. 一塊最多 60 行，只做一件事，各有自己的 `out`。第 0 章寫 lab 檔案、寫到磁碟的腳本不受此限。
10. 不在貼上的指令裡用 `exit`（會關掉終端機）。「先檢查、後動手」拆成兩塊。
11. `run-full.sh` 每塊用 `trap … ERR` 執行，任何一行失敗就停，所以「失敗才正常」的指令要這樣寫：
    - 等服務起來：`if curl -sk -f -o /dev/null "$url"; then break; fi`（`-f`：HTTP 400 以上算失敗）。
    - 要比對狀態碼：`if [ "$(curl -s -o /dev/null -w '%{http_code}' "$url")" = 401 ]; then`，或放在 `echo` 的參數裡。不要寫 `code=$(curl …)`，連不上時那一行會觸發停止。
    - 計數可能是 0：用 `awk '/…/ {c++} END {print c + 0}'`，不用 `grep -c`（找不到時結束碼是 1）。
12. 送到遠端的整段腳本用 `bash -e -s <<'EOF'`，只看不改的檢查用 `bash -s`；要傳值用 `bash -s -- 值`，heredoc 加引號，不再跳脫。
13. 指令改寫不改變行為。`out` 區塊要和新指令實際印出的內容一致。Windows 終端的區塊跑在 Git Bash，沒有 `python3`。

## 腳本（install、opmenu）

14. 共通規則都適用。腳本可以有函式：函式上面寫一行用途與輸入輸出例子。
15. opmenu 另外沿用 `opmenu/README.md` 的項目檔格式；改完跑 `opmenu/tests/` 的全部測試。
16. 不改變行為、結束碼與輸出格式。

## 分組（cbom/ 底下的腳本；2026-11-13 定案）

17. 做同一件事的連續幾行是一組：每組上面一行註解說這組在做什麼，組和組之間空一行，組內不空行。
18. `fi`、`done`、`esac`、函式的 `}` 結束之後，和下一組之間空一行（緊接著另一個結束、`else`、`;;` 時不用）。lint：「結束後沒有空一行」。
19. 一行一個指令，不用 `;` 把兩個指令放在同一行；一行寫完的小函式也拆成三行（`;;`、`; then`、`; do` 是標準寫法，不算）。lint：「一行兩個指令」。

第 18、19 條目前只對 `cbom/` 檢查；`install/`、`opmenu/` 與手冊還沒照這兩條排過（量過約 180 筆），之後要套用時改 `lint-commands.js` 的 `usesGroupRules`。第 17 條（怎麼分組）要靠人讀，lint 不檢查。

## 例外

真的改不了的行，在同一行或上一行加註解 `# lint-ok: 原因`。原因要寫得出來；只因為比較短不算原因。
